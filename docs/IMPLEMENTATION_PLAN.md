# FreeShow-rs 1.0 implementation plan

This plan covers the work from a functioning native presenter to a release a volunteer can confidently prepare, hand off, and run. See the [roadmap](ROADMAP.md) for release order, the [migration plan](MIGRATION_PLAN.md) for architecture and existing budgets, and the [parity inventory](PARITY.md) for compatibility coverage.

The code review used local main at `d125071`, the tracked `origin/main` at `bdaf1a5`, and the in-progress preview changes in `main.rs` and `present.rs`. The tracked branch already contains operator styling, an RGBA picker, a collapsible inspector, notes, and canvas selection, move, and resize. Start implementation by checking the integrated state and preserving those improvements. Current coverage below comes from inspecting code and workflows. New capabilities and numerical targets are proposed.

## 1. Operator experience and safe edits

**First workflow.** Open an existing library or start from an original template, build a run order with songs, scripture, slides, and local media, rehearse it on the confidence monitor, and run it from the operator window or phone. Keep the service controls reachable even while someone is editing.

| Surface | Design and behavior |
| --- | --- |
| Present | Keep the current project navigation and slide cards. Give live cue, selected cue, upcoming cue, and cleared output distinguishable text and visual states. Put Go, Previous, Next, and Clear in consistent places and surface audio mute and output connection status. Selecting and taking a cue are distinct actions in the default workflow. |
| Edit | Make the canvas the primary area. Organize around a project or slide navigator, a zoomable canvas, contextual tools, and the existing inspector. Keep a Layers view and the Media and Templates drawers one action away. Collapse secondary panes in compact windows. |
| First run and empty states | Offer Open Library, New Project, and Use a Template where relevant. Offer a sample service with original starter designs. Use a rehearsal path for display and audio checks before going live. |
| Feedback | Put Saving, Saved, and Save failed near the document. Show missing fonts, media, or displays with the relevant recovery action. Reserve blocking dialogs for decisions that could lose work or interrupt output. |
| Visual language | Keep the familiar FreeShow layout and existing 8 px spacing rhythm. Use consistent spacing, type sizes, focus outlines, and buttons across light, dark, and imported themes. Use one primary accent for actions and a distinct tagged state for live output. Use subtle local feedback for selection and panel changes. |
| Accessibility | Give custom controls roles and names, preserve visible focus, expose toolbar and layer actions through keyboard and click controls, and offer numerical geometry fields as alternatives to dragging. Verify keyboard-only operation, screen-reader announcements, contrast, and scaled layouts. Provide reduced operator motion independently of the authored program. [Slint accessibility properties](https://docs.slint.dev/latest/docs/slint/reference/common/) · [WCAG 2.2](https://www.w3.org/TR/WCAG22/) |

### S1. Make editing, preview, and program independent

- Trace selection, Take, Clear, auto-advance, live edit refresh, and remote commands through `main.rs`, `session.rs`, `live.rs`, and `present.rs`. `edit_frame` already renders the selected slide separately. `note_live_edit` currently flags on-air shows for repaint. Keep a taken content snapshot in the existing program state, including resolved slide content and its cue identity. Continue sampling live video, clocks, timers, and intentional runtime controls.
- Apply authoring changes in Edit. An explicit Take or Update Live publishes the new revision for that cue. If existing libraries rely on live updates, provide a clearly labeled compatibility setting or migration choice. Preserve imported click-to-go settings and verify how they interact with Edit mode before changing defaults.
- Make trigger side effects explicit. Preview, cancel, undo, and Update Live must leave timeline and audio triggers alone. A new Take runs the cue as specified. Resolve concurrent local, remote, and scheduled commands deterministically through the existing session.
- Check Go and Clear during a drag, a failed save, and a disconnected display. Test that the same cue and revision are reported by the UI, stage view, and remote after each command. Verify that typing into a text field cannot fire a presentation shortcut.

### S2. Make edits durable and undo predictable

- Reuse the JSON-preserving setters in `freeshow-data/src/item_edit.rs`, the session snapshots, and atomic writes. Introduce a single commit path for editor gestures and commands. Capture the target by show ID and slide ID, with item identity scoped to the current slide revision. Resolve the undo/redo target before mutating history. The current code can fall back to a show index and ignores an undo-save error. Add cross-show, deleted-target, and save-failure regression cases.
- Treat dragging, resizing, and slider adjustments as transient updates. Commit once on release or confirmation. Cancel restores the original state. Text edits commit on a deliberate boundary such as accepting the edit or leaving the field. Group edits, paste, apply template, and undo each have a clear history boundary.
- Track dirty document revisions and render/save from immutable snapshots. Start with ordered per-file saves and bounded work. If a save moves off the UI thread, serialize writes per document and ignore stale completions. Keep a failed draft available for retry or recovery and expose conflicts from changed files on disk. Reuse library backups and validate recovery after a forced exit. Protect an existing library during fixture and migration tests.
- Pass when a user can switch shows, undo the original edit correctly, reopen the library, and recover the latest draft after a failed save or forced exit. Verify unknown JSON fields after edit, undo, re-open, and export.

## 2. Transitions and object animation

**Current path.** `TextTransition` carries kind, duration, direction, and easing. `live::motion_frame` reuses headless effects, including fades, slides, pushes, wipes, cover/uncover, scale, blur, and spin. `main::fade_into` and the video opening fade schedule playback separately. The still fade ticks every 40 ms and stores the target as the last output before the fade finishes. Rapid Takes need a defined handoff from the last displayed frame.

| Slice | Implementation and acceptance |
| --- | --- |
| M1. Make existing effects discoverable | Add a visual preset picker for Cut, Fade, Dip to Black, Push, Wipe, Cover, and the other existing effects. Offer duration, direction, easing, reset to inherited, and apply to selected slides. Label the effective source of the preset. Clear and video end cues retain their dedicated handling. Normal Takes resolve the matching slide override, output style, then library default, separately for text and media. Check how transition-change actions affect subsequent Takes. Preview from the actual adjacent slides without sending frames or audio to program. |
| M2. Make the playback path predictable | Reuse a clock-driven sampler for preview, still Takes, and video opening where inputs permit. Publish the first sample promptly and invalidate old work on Take, Clear, or output resize. Start interrupted transitions from the last displayed frame when available. Bound frame work and retain one latest pending frame per surface as needed. Preserve stage behavior, timer deadlines, auto-advance, transition sound, media audio, and output routing. Use the same transition result for consumers of the same program output. |
| M3. Add object builds | Ship entrance and exit Fade, Move, and Scale, a simple ordered build list, and On Take, With Previous, After Previous, and On Click triggers. Keep animations deterministic by sampling explicit cue time. Define how Next consumes builds before advancing, and how Previous, direct Go, auto-advance, and stage/remote readback handle them. Fall back gracefully when an older app encounters native extensions. |
| M4. Evaluate shared-object motion | Prototype a Morph-style effect when adjacent slides explicitly share stable object identities. Start with position, size, opacity, and rotation, and fade unmatched objects. Benchmark text, shapes, and media before expanding the effect set. Keep this stretch work behind object builds and preview/live parity. [Microsoft Morph workflow](https://support.microsoft.com/en-gb/powerpoint/training/use-the-morph-transition-in-powerpoint) |

Test output fingerprints at start, midpoints, and completion, plus repeated Next, immediate Clear, video first frame, long cue gaps, media fallback, multi-output, and authored transition on imported PowerPoint. Check that repeated preview leaves history and program unchanged. Support a rehearsal bypass and an explicit live cut override for services that need it.

## 3. Templates and portable handoff

1. **Template browser.** Reuse the existing template catalog, thumbnails, and lyric-preserving application. Add search, preview, favorites, and original starters for lyrics, scripture, announcements, titles, and service countdowns. Offer Use as New, Apply Style, and Save as Template with distinct semantics. Use as New creates an independent copy. Apply Style preserves slide order and content, with a preview for destructive structural changes. Support editable placeholders and keep the original template intact.
2. **Export and import.** The current compatible project archive writes `project.json` with project, shows, and optional overlays. The existing reader in `freeshow-data/src/import/community.rs` can load declared bundled media by basename. Preserve the compatible export and use that reader as a starting point. Add a portable template/project bundle with versioned metadata, selected slides or project references, preview, and enumerated dependent assets. Run a package round trip in reference FreeShow before deciding whether the portable extension can share the same format. Use relative asset IDs and report remote-only media, missing files, fonts requiring installation, and items excluded from export. Bundle licensed assets only, and default to excluding private notes and unrelated library contents in template shares.
3. **Resolve safely.** Preview bundle contents before import. Stage and validate the archive and referenced assets before committing. Enforce bounded extraction, containment, and validation of file names and types. Detect collisions by ID and content. Default to making a new copy with remapped internal references. Reuse identical assets and report unresolved references for relinking. A failed or cancelled import leaves the original projects, shows, and assets intact. Restore or clean up staged writes if a later commit step fails.
4. **Acceptance.** Export a service with a template, a video, two same-named pictures, a non-bundled font, and a private note. Import it with a clean profile on another OS while offline. Verify editable text, cue order, media playback, font relink, note exclusion in template share, and no overwrite of an existing show. Check malformed archives, rejected entries, interrupted imports, and repeated import.

Canva’s template workflow provides a way to reuse a design independently. The first FreeShow-rs handoff uses local files that can travel by drive, email, or an existing team share. Hosted sharing, accounts, and collaborative editing can follow demonstrated demand. [Canva template sharing](https://www.canva.com/help/share-template-link/)

## 5. Performance and release verification

Use the existing `--check-library`, `--check-service`, `--check-perf`, and packager as the headless baseline. Add a repeatable installed-app run with timings at input, first published frame, and first visible output where practical. Record build SHA, hardware, graphics backend, displays/DPI, OS, fixture, and p50/p95 from repeated runs on an idle machine. Keep UI and headless measurements separately labeled.

| Check | Proposed release evidence |
| --- | --- |
| Startup and responsiveness | Operator usable within 1.5 s on the reference mid-range laptop, 1,000-show library usable within 500 ms, editor input-to-visible preview p95 ≤ 50 ms during drag, and local Take to first visible output p95 ≤ 50 ms. Keep the existing ~16 ms render-path target separately. Record LAN remote-to-visible output and target p95 ≤ 100 ms on a documented network. Baseline on each OS before locking tolerances. |
| Live workload | Retain the existing 1080p targets of 60 fps for stills and at least 30 fps for video, with no audible underruns. Run a 90-minute mixed service with audience and stage open, transitions, video, and periodic remote actions. Record frame stalls, audio errors, and memory after warm-up. Use the existing ≤ 150 MB idle target and investigate sustained growth. |
| Authoring under load | Open the large library, filter the catalog, scrub transition previews, and edit layers while video is on air. Measure UI time for saves, refresh work, thumbnail misses, and uploads. Profile before changing render backends. Exercise high DPI and the software path where supported. |
| Failure and compatibility | Kill during save, reopen, verify undo and recovery, remove media, unplug a display or audio device, drop the network, reconnect the phone, and try a bad password. Run clean-install and upgrade/rollback on a copy of a real library. Keep credentials out of logs and shared bundles. |
| Usability and polish | Run a first-time operator and an experienced operator through compose, import, rehearse, Take, recover, and hand off. Record completion, time, errors, help requests, and accidental live actions. Repeat keyboard-only and on representative screen readers. Resolve blockers and repeat the affected flows. |
| Distribution | Run fmt, clippy, workspace tests, service smoke, and clean install/upgrade on each advertised OS. Start with the current release Gate and package workflows. Add PR-time targeted checks for regressions that should be caught before packaging. Track macOS Developer ID/notarization, Windows signing/reputation, runtime licensing and dependencies, and a rollback procedure. Publish actual signing and platform support status. |

| 6 | Build animations and offline media workflow | Object builds follow the transition runner. Authorized local media import and reliability testing can progress alongside it. |
| 7 | Finish preflight, operator tuning, and release rehearsals | Start measurements and rehearsal early. Close release blockers before expanding integrations, hosted sharing, or import edge cases. |

For every slice, update the parity inventory and user instructions when the behavior lands. Record test commands, OS and fixture, and focused visual evidence for UI changes. Mark a slice complete once its acceptance case runs through the normal app entry points. Track release blockers by reproduction, affected platform, owner, and verified fix. Open issues that can remain at release need a documented workaround and must preserve library data and the live service path.
