# Using FreeShow-rs

How to run the app, what it reads from a FreeShow library, and how each integration is configured. For build and packaging see [PACKAGING.md](PACKAGING.md); for feature status see [PARITY.md](PARITY.md).

## Running

Install Rust 1.97 or newer and GStreamer 1.x (macOS: `brew install gstreamer libnice-gstreamer`). On Apple Silicon, point pkg-config at Homebrew before building: `export PKG_CONFIG_PATH="$(brew --prefix)/lib/pkgconfig"`. Video and cameras use GStreamer. Camera selection opens the device returned by native discovery rather than guessing its device index. Compressed camera feeds use a software decoder to produce CPU-readable frames. A disconnected camera reports an error; raw and JPEG camera feeds share the video decoder. Physical-camera testing remains pending. Audio uses the system output device. Then from this directory:

```sh
cargo run -p freeshow
```

Point it at an existing FreeShow library, or open one show:

```sh
cargo run -p freeshow -- --data ~/Documents/FreeShow
cargo run -p freeshow -- --show ~/Documents/FreeShow/Shows/Some\ Song.show
```

`scripts/present-sample.sh` builds a one-song library and opens the first slide on the output window.

## Running a service

Open a show from the drawer or the project list. Its slides appear as thumbnails and stay in view while you browse media, audio or other drawer tabs. Clicking a slide puts it on the output, as in FreeShow; the arrow keys, Page Up/Down (presentation clickers) and Space step through it, from the operator, output or stage window. The live slide carries a LIVE tag and the panel beside the slides shows the real output picture. Under it, **Clear all** (or Esc) blanks everything, and **Slide**, **Background**, **Overlays** and **Audio** clear one layer each.

**Edit** switches the show to editing: clicking a slide then only selects it, the preview shows the slide being edited, and **Go** puts it on the output. **New show** opens straight into editing, and **Show text** edits the whole song as plain text.

To place a picture on a slide, choose a still image from the Media library picker in **Edit** and click **Add picture**. The new box opens in the inspector, where you can change its position, size, fit, crop, or flips. Keep the source file in place so the slide can display it.

On slides with several boxes, use **Move backward** or **Move forward** to change which box appears on top where they overlap. Box numbers follow the saved order, including when a stage layout is set to display a specific box number.

Drop songs, pictures, video, audio, or Bibles onto the operator window to import them into the open library. When a file cannot be copied, the status bar reports the failure and the rest of the batch continues.

Audience slides and the native stage window render saved FreeShow QR boxes with their configured payload and colors. The code stays square in a rectangular box. A Current Output box previews the active audience picture on the native stage and its browser view, with the saved output name when requested. Stage text boxes honor saved text-box numbers, item order, and stage bindings for multilingual slides.

Put song sources in the library `Imports/` folder before opening the library. ProPresenter 4–6 XML (`.pro4`, `.pro5`, `.pro6`) and `.proBundle` archives import lyrics, group children, disabled slides, notes, and slide backgrounds. Bundled media is copied into `Media/` and the saved shows point there; existing files are kept, and matching media is reused on repeat imports. Missing or ambiguous bundle media produces an import warning instead of linking to another file. ProPresenter 7 `.pro` files and bundles retain cue groups, the selected arrangement, slide notes, backgrounds, and separate text boxes with saved bounds and box-level typography. Mixed RTF runs preserve fonts, sizes, colors, bold, italic, underline, strikethrough, paragraph alignment, all caps, and letter spacing within the box. Legacy RTF hex escapes use the declared document code page or font charset. Imported lyrics and notes preserve typographic punctuation and spacing and omit hidden RTF text. Audience output draws imported text highlights and character background colors behind their runs. Rectangles, ellipses, triangles, rhombuses, regular polygons, and stars retain their placement and layer order, with solid, linear, or centered radial fills. The Rust compositor applies stored rotation to ordinary slide items. Timed cues can advance within the selected arrangement, return to its first eligible slide, or jump to the first eligible occurrence of a specified cue. The timer also runs during background playback. Immediate global clear-audio and clear-background cues use the native slide actions. Standalone audio and background clears keep the last slide on the audience and stage. Imported timeline slides, background pictures and videos, and global Clear Slide, Clear Audio, Clear Background, and Clear All actions play at their recorded times in the selected arrangement. Background media cues keep the current slide visible. Foreground pictures and videos cover the current slide and clear when another slide is triggered. Imported foreground videos are audible by default. Imported videos can hold the last frame, stop on black or clear, or fade to black or clear. Fades use the native media transition duration. Imported timeline soundtracks play through the native audio output and restart when the timeline loops. Imported audio cues can start a file on a slide or at a recorded timeline time and honor its loop and retrigger settings. Audio cues and soundtracks share the native audio player. Timelines marked to loop repeat at their saved duration. Without a saved duration, they loop after the last cue and soundtrack playback. Other tracks and unsupported graphics and cue actions remain incomplete. Bundles are limited to 10,000 entries, 16 MiB per presentation, 512 MiB per media file, and 2 GiB uncompressed in total. MediaShout XML/SSC and JSON table dumps, Quelea XML/`qsp`, SoftProjector `.sps`, EasySlides, VerseView, VideoPsalm, CSV, image-only shows, and FreeShow project packages (JSON or zip) also import from `Imports/`. Native MediaShout `.mdb` and Canva presentations are not imported.

PowerPoint `.pptx` imports keep the presentation's saved slide order and hidden slides. Speaker notes are imported as plain text for stage layouts with a Notes item. Saved automatic advance timings use FreeShow slide timers when the deck enables timings. Named custom shows and saved slide ranges become FreeShow arrangements. FreeShow opens the saved selection and keeps the full deck available as an arrangement. A timed final slide restarts the selected arrangement when the deck enables looping. Cuts, fades, fades through black, pushes, wipes, covers, and uncovers use the saved visual duration when available. Cover and uncover preserve corner directions. Legacy speed presets are approximate, and other effects use the FreeShow transition settings. PNG and JPEG backgrounds can be inherited from a layout or master. Embedded images are copied into `Media/` with their stretch and crop. Linked image backgrounds keep their URL, and tiled backgrounds repeat across the slide. Theme fills use the deck’s style matrix and the active slide color map. Backgrounds preserve tint, shade, luminance, opacity, and gamma adjustments, along with linear and circular gradients. Linear gradients preserve fractional angles and PowerPoint’s aspect-ratio scaling. The Rust compositor preserves radial point and elliptical focuses and rectangular focuses inside the slide for direct and theme fills. Shape paths on slide backgrounds follow the slide rectangle. Unspecified focus edges use the Office center defaults. Fractional gradient stops retain narrow color bands. Explicit empty stop lists fill black, and a one-stop fill uses its solid color. Eligible two-stop and three-stop gradients use PowerPoint’s per-channel gamma. Gradient tile rectangles preserve signed edge offsets and repeat with mirrored neighbors. Unusual tiled path gradients may differ from PowerPoint. Positioned shapes and text boxes keep direct and theme gradient fills. Ellipse shape paths follow the ellipse, and rectangle shape paths follow the box. Positioned objects keep their rotation. Pictures keep both flips and their source crop. Shape flips also reflect gradient fills. Fills with Rotate with shape disabled keep their orientation in slide coordinates. Nested groups keep their transformed positions, scales, rotations, flips, and stacking order. Their children import as individual items. Positioned text keeps mixed font sizes, Latin theme fonts, run colors, highlights, bold, italic, underline, strikethrough, and letter spacing. Mixed sizes share a baseline, with room above and below it for the largest text. Wrapping keeps words together across formatting changes. Unicode break points allow ordinary breaks in Chinese and Japanese, honor nonbreaking spaces, and keep combining marks with their base characters when an oversized word must split. Paragraph alignment, vertical anchoring, explicit line breaks, text-box insets, line and paragraph spacing, and paragraph margins and indents also import. PowerPoint text boxes with wrapping disabled keep their explicit line breaks. Text remains clipped to the shape bounds. Saved normal autofit imports the font scale and percentage line-spacing reduction. FreeShow keeps these values when text is edited. Character bullets and automatic numbering preserve inherited font, size, and color. Decimal, Latin alphabetic, and Roman schemes retain start values and nested list counters. Other numbering schemes use decimal markers. Picture bullets, complex text transforms, and extended gradient geometry remain incomplete.

While the app is running, a phone on the same network can open `http://<this-computer>:5510/` to change slides. A stage page is at `http://<this-computer>:5511/`. It shows the native stage layout, including its clocks, timers, notes, still images, and QR codes. The ports come from the library `settings.json` when it sets `ports.remote` and `ports.stage`. Native stage layouts honor next-slide boxes and clock dates saved in older FreeShow libraries. Local stage video boxes loop silently. A slide-text box with `includeMedia` mirrors the current audience background or shows the still background of its offset slide. The stage editor lets you turn this on, choose a text box by number, and reverse box order when showing all boxes. The stage port serves layouts and current output and ignores show-control commands. Both speak FreeShow's message shape, `{ "channel", "data" }`, on a WebSocket at `/ws` and on the Socket.IO events `REMOTE` (remote port) and `STAGE` (stage port). When the library `settings.json` has `serverData.remote.password`, both pages ask for it and every socket connection must send `ACCESS` with that password before any channel is answered. The password is sent as the `x-freeshow-password` header on the page's HTTP requests. Channels that move the show are `API:next_slide`, `API:previous_slide`, `API:index_select_slide`, `API:clear_all`, `API:clear_slide`, `API:clear_background`, `API:clear_overlays`, `API:clear_audio`, `SHOW`, and `API:start_scripture`. `GET_SCRIPTURE` and `SEARCH_SCRIPTURE` read the Bibles in the library. `API:scripture_next` moves to the next verse. On connect the remote also receives `PROJECTS`, `FOLDERS`, and `PROJECT`. `SEARCH_SHOWS` finds a song, and `API:set_plain_text` saves lyric slides separated by a blank line. `API:create_project`, `API:rename_project`, `API:delete_project`, and `API:remove_project_item` edit the service list. `API:get_groups` lists verse and chorus groups. `API:change_layout` switches a song to another layout. `GET_TEMPLATES` and `API:set_template` list templates and apply one to the open song. `API:id_start_timer`, `API:id_pause_timer`, and `API:id_stop_timer` run a countdown from the library. `API:id_select_overlay` draws an overlay on the audience. `API:play_media` plays a file from the library, `API:pause_audio` holds it, `API:audio_seekto` and `API:video_seekto` move the playhead, `API:toggle_media_loop` turns background looping on or off, and the volume slider on the phone page sets the main output level.

Use the Layout menu in the stage editor to switch between saved layouts. New layout starts with an empty stage. Duplicate layout opens a separate copy of the selected layout, including hidden boxes. Set its name and background color, then press Enter in each field to save. The preview and stage frame use the first configured stage output’s resolution when it has saved bounds. Without those bounds, they use the audience resolution. Click a box in the preview to select it. Where boxes overlap, the front box is selected. Hidden boxes can be selected in the list. Select a box and drag its outline in the preview to move it. Drag the lower-right handle to resize the box. Position and size changes save when you release the pointer. Use Move backward or Move forward to change which box appears on top when they overlap. Turn off Show on stage to hide a box and use the same switch to restore it. Hidden boxes stay in the editor and in the saved stacking order. Set a box label to identify it in the list, and clear the label to restore its default name. For slide text or notes, a slide offset of 0 follows the current slide, 1 follows the next slide, and −1 follows the previous slide. The selection is restored when you reopen the library. The stage editor saves changes to the layout shown in its preview, including after a slide action switches layouts. In the stage editor, add a QR code box and enter the content and colors. Clear the background field to make it transparent. An output picture box previews the active audience output. Choose a named output to show the picture only while that output is active, and turn on Show output name to label it. Add a camera box to select a connected camera, choose how it fits the box, and flip it horizontally or vertically. Reopen the stage editor to refresh the camera list. Add a chart box and choose Bar, Line, or Pie. Enter one `Label: value` per line or paste FreeShow JSON chart rows, then select Apply chart data. For a doughnut chart, choose Pie and set the hole size above zero. Add a Web preview box for a static page-address card. An optional local still image takes precedence over the card. Clear the still image field to return to the card.

Audio files and video sound follow the library's `audioRouting.connections` graph through `audioChannelsData` mixer gains to the default speaker or named speaker devices. Slide audio and drawer audio use `drawer_audio`; playlists use both `playlist_sub_<id>` and `playlists_default`. A source with no speaker connection stays silent. The phone page lists mixer channels and lets you set each channel's volume and mute independently. Main affects paths through the Main channel. Video sound uses `output_window` and `output_win_sub_<audience-output-id>` and keeps the clip's stored volume.

FreeShow's named speaker IDs come from Chromium and need a native device mapping. Run `cargo run -p freeshow -- --list-audio-devices` for audio-file devices or `cargo run -p freeshow -- --list-video-audio-devices` for video speaker devices, then add the exact device name to this app's `settings.json`, for example:

```json
{"audio_devices": {"speaker_sub_<FreeShow-device-id>": "Stage Speakers"}}
```

Keep the other app settings when adding that field. An unavailable mapped device logs an error and does not fall back to the room speakers. Audio-file speaker devices and network feeds use independent playback clocks. Video sound uses GStreamer speaker sinks on its playback clock. Hardware speaker connections honor `channelIndex`/`toChannelIndex` and an explicit `fromChannelIndex`. A single selected speaker port receives a mono mix; multiple selected ports preserve the corresponding source channels. Named speaker connections without an index use port 0, as FreeShow does. Audio and video share the same channel matrix, and unmapped ports stay silent. Changes to video channel routes and their mixer gains take effect during playback. Active video audio branches apply the latest queued route on the streaming thread when the next buffer arrives. Indices are zero-based and must be below 64; unavailable device channels fail without falling back to the room speakers. Stereo network feeds follow `network_sub_<output-id>` routes and keep audio-file and video sources separate until the sender mixes them. A network-only audio file needs no physical output device. The PCM effects chain supports gain, peaking EQ, delay, compressor, and limiter.

Icecast sends stereo Ogg Opus through the saved audio route to the `icecast` node. It reads `special.icecast` from the library's `settings.json` and only opens a configured stream when the graph has an Icecast connection and the node is enabled. **Functions → Enable/Disable Icecast**, slide actions, and the password-gated `API:toggle_icecast` command update that saved setting. It requires the GStreamer `shout2send` plugin. Windows builds can stream when their SDK includes it.

OSC input listens on UDP port 5505, the same port FreeShow uses. `/freeshow/slide/next`, `/freeshow/slide/previous`, `/freeshow/slide/1`, `/freeshow/clear/all`, and `/freeshow/show/<id>/start` drive the open show.

MIDI input opens the first connected input, or the port named by `FREESHOW_MIDI_IN`. FreeShow's default notes are used: channel 1 note 0 is next, note 1 is previous, channel 3 note 0 clears, and channel 5 note 2 selects a slide from the velocity.

Each enabled, ungrouped NDI output in the library sends its picture and routed stereo audio through the GStreamer NDI plugin. Audience outputs send the audience picture; stage outputs send the stage picture. A source name uses `ndiData.name`, or `FreeShow NDI - <output name>`. With no enabled NDI output, nothing is broadcast. The plugin and NDI SDK runtime are required. Grouped outputs stay disabled because the current sink does not expose NDI discovery groups. Each enabled OMT output advertises its audience or stage picture over the local network and sends its routed stereo mix. It uses `omtData.name`, or `FreeShow OMT - <output name>`. OMT sending is built into FreeShow. Enabled WebRTC outputs encode H.264 and stereo Opus through webrtcbin. Each WHIP stream uses the saved mix routed to `network_sub_<output-id>` and publishes to `webrtcData.url` with an optional Bearer token.

To start with a network video background, set `FREESHOW_OMT_IN` to a discovered name such as `BOOTH (Lobby)` or a direct URL such as `omt://192.168.1.20:6400`. You can also set `special.omtInput` in the library’s `settings.json`. For a GStreamer NDI source, use `FREESHOW_NDI_IN` or `special.ndiInput`. During a service, open **Media** and click **Find network sources**. Choose an NDI or OMT feed and click **Use source**, or enter a direct OMT address and click **Use OMT address**. The feed plays behind slides until you clear or replace the background. Use the picker again to restart it.

MIDI timecode uses the first input, or the port named by `FREESHOW_MTC_IN`. Quarter-frames and full frames replace the stage clock with `HH:MM:SS:FF` while they are arriving. Linear timecode listens only when `FREESHOW_LTC_IN` names an input (`default` uses the system input) and uses 25 fps unless `FREESHOW_LTC_FPS` is set.

Functions → Record writes the audience picture to `Recordings/freeshow-YYYYMMDD-HHMMSS.mp4` in the library. Choosing it again, or closing the app, closes the file. Local MP4 recording is still video only. `FREESHOW_RTMP` streams the current picture with routed stereo AAC audio to that URL. It uses the first enabled RTMP output ID in the library, or `default` when none is configured; route to `network_sub_<id>` to feed it. Saved `rtmpData.destinations` can start through their auto-start flags or `special.autoRtmp`. The app supports one active RTMP destination. Static pictures repeat at 30 fps so media audio can continue without slide changes. The RTMP pipeline corrects source timing gaps up to 250 ms. Network feeds require the GStreamer `inter` plugin; RTMP also requires an AAC encoder (`avenc_aac`).

Planning Center loads when `FREESHOW_PCO_TOKEN` is a Services access token and `FREESHOW_PCO_PLAN` is `serviceTypeId/planId`. `FREESHOW_PCO_FILE` can point at a saved plan document instead. Songs and plan items become shows, headers stay section labels in the project, and Functions → Planning Center loads the plan again. With neither a token nor a file, the app does not contact Planning Center.

ChurchApps loads the presenter plans for `FREESHOW_CHURCHAPPS_TOKEN`, or a saved plan from `FREESHOW_CHURCHAPPS_FILE`. Arrangement lyrics become shows, with later lyric blocks kept as child slides, and Functions → ChurchApps loads them again. Without a token, service-plan API requests are disabled.

Lessons.church `.olp`, `.olf`, and lesson `.json` files in `Imports/` are imported at startup or through Functions → ChurchApps, without an account. `FREESHOW_CHURCHAPPS_FILE` can also point at one lesson document. Cover images and media from playlist groups or OLF `play` actions download over HTTP/HTTPS into `Media/Lessons/`. The resulting shows are added to the `Lessons.church` project only after every media download finishes. Grouped slides keep video loop flags, audible video sound, and advancement after a non-looping video except on the final slide. Completed downloads are cached for offline reuse; repeated imports keep operator edits. Failed or truncated transfers do not publish a lesson and can be retried. Limits are 16 MiB per source file, 2,000 media slides, and 2 GiB per media file. Downloads run in the background at startup or after the Functions action. The footer shows downloaded bytes for the current file and offers Cancel import. Cancellation waits for any in-flight network read to return before cleaning up the partial file. Completed media stays cached. Service-plan publication keeps unrelated project edits and skips the refresh if an imported project changed during preparation. Service-plan lesson sections, actions, and add-ons also use this local media cache. Venue plans resolve their public feed, and a venue service with no custom order follows its playable feed actions. Uncached add-ons use the public add-on lookup. Service-plan media stays in service order, keeps its explicit loop flags, and stores scheduled durations. Failed metadata or media requests keep the previous service and show files. Saved service-plan documents must include the resolved `files` arrays on lesson children. Public lesson and media requests do not carry the service account token. Vimeo, YouTube, and other stream-only items are published with their remote URL as the media path and are not downloaded. Direct HTTP video files play through GStreamer. YouTube and Vimeo pages can play when `yt-dlp` is installed and resolves a playable stream.

Functions → Backup writes `Backups/YYYY-MM-DD_HH-MM.zip` with shows, portable config, and bibles in the FreeShow backup names. Functions → Restore puts the newest of those zips back into the library. `FREESHOW_CLOUD_DIR` also receives a copy, and `FREESHOW_CLOUD_URL` receives a PUT of the zip (`FREESHOW_CLOUD_TOKEN` is sent as a bearer token when it is set). A failed copy or upload keeps the local zip and the show continues. When neither destination is set, the app does not upload on startup. Functions → Export PDF, Export package, and Screenshot write a lyrics PDF, a `.project` zip of the open project, and a PNG of the current audience frame under `Exports/`. Functions → Metronome starts and stops a beat from the stored `metronome.tempo` (or `bpm`) and `beats`; the footer also shows a configured `timecode` mode. When `fullColors` is on, slide labels use the group color as a fill; otherwise a color bar marks the group. `slidesOptions.columns` and `mode` lay the slide list out as a grid, except `list` and `lyrics`, which stay one column. The show/media drawer sits along the bottom at `drawer.height` (default 300px) and is hidden in focus mode. A first-run guide appears until dismissed. Functions → Undo / Redo, Focus mode, Guide, Kiosk, Always on top, and Shortcuts match the default chords Ctrl+Z, Ctrl+Y, Ctrl+Shift+F, Ctrl+F1, F11, and Ctrl+Shift+A; Functions → Shortcuts edits those bindings. As in FreeShow, Esc or `.` clears everything, F1 clears the background, F2 the slide, F3 the overlays, F4 the audio, and F5 goes to the next slide.

OBS uses WebSocket 5. `FREESHOW_OBS` is `host:port` (port 4455 when the host has none) and `FREESHOW_OBS_PASSWORD` is the server password. When those are unset, the library `obsData` (`ip` or `host`, `port`, `password`) is used if it is enabled. Functions → OBS scene sends `SetCurrentProgramScene` for `FREESHOW_OBS_SCENE`. Functions → OBS stream and OBS record start and then stop that output. When `FREESHOW_OBS` and `FREESHOW_OBS_SCENE` are both set, the scene is selected at startup. A closed OBS is logged and the show continues.

Functions → AI rewrites the selected slide through Ollama when `FREESHOW_AI` is `ollama` or a base URL such as `http://127.0.0.1:11434`. `FREESHOW_AI_MODEL` defaults to `gemma3:4b`, and `FREESHOW_AI_PROMPT` is the instruction. The model replies with slide lines, which replace the selected slide. With `FREESHOW_AI` unset, the app does not contact a model.

Every 15 minutes the open shows and the project file are saved again. A file whose bytes did not change is left alone, so the `Backups` folder does not grow. Each save still writes a temporary file, flushes it, and renames it into place.

## Windows and configuration

The operator window is Slint. Audience and stage windows show frames rendered by the `freeshow-output` crate and uploaded with wgpu. Those frames are not drawn as Slint widgets.

Settings and the log are stored in the app config directory:

- macOS: `~/Library/Application Support/freeshow-rust/`
- Windows: `%APPDATA%\freeshow-rust\`
- Linux: `$XDG_CONFIG_HOME/freeshow-rust` or `~/.config/freeshow-rust`

`FREESHOW_CONFIG_DIR` overrides that path. `settings.json` holds the theme name (when set), the FreeShow library path, and whether the output and stage windows open on launch. When no theme is set here, the library's own FreeShow theme is used. Custom theme colors and fonts are read from `Config/themes.json` using the theme ID selected in the library settings. The library `settings.json` also supplies `outLocked`, `lockedOverlays`, `splitLines`, and the other keys listed in `PARITY.md`; locked overlays stay on when a library opens, and `outLocked` blocks output changes. `splitLines` splits imported and edited lyric pages, `customFonts` files are used when a slide names that family, and `resized` left/right panel widths size the operator lists. The header Search box filters the current drawer tab. Missing or malformed values keep the built-in defaults. Font family and `em` font size apply to the operator window; unavailable fonts use the system fallback. `RUST_LOG` controls stderr tracing (default `info`).
